# Training-data assessment — 5 candidate SFT/DPO sources

Answers one narrow question: **can any of these five datasets improve the next training round of
funnypot's 0.5B (`Qwen2.5-Coder-0.5B-Instruct`)?** Companion docs: `../LLM-TRAINING-DATA.md` (the
broader sourcing plan — real-software recording via warcprox is still the big lever), `../LLM-TRAINING-
STRATEGY.md`/`../LLM-TRAINING-BRAINSTORM.md` (why distillation beats raw-inversion fine-tuning), `honeypot-
projects.md` (Galah and dd-honeypot are already surveyed there for *technique* theft — this doc adds the
*training-data* verdict). Current state: a self-distilled LoRA (`funnypot-llm/train/`, mlx-lm, chat format
`{"messages":[{system},{user:"GET /path"},{assistant:HTML}]}`, 200/20/20 split, val loss ~0.22, servable-HTML
3/20 → 20/20 on the base model) — see `funnypot-llm/train/README.md`.

Sources checked 2026-08-19 via HF API + dataset card + row sample (`klukama/*`), and shallow `git clone
--depth 1` (galah, dd-honeypot, honeyval) into a scratch dir.

## The fingerprint-safety filtering gate — run this first, on everything

funnypot already has a proven gate (`funnypot-llm/train/generate-corpus.php`'s corpus validation):
reject any candidate row containing `nuclei`, `CVE-`, `matcher`, `interactsh`, `{{BaseURL}}`, or similar
nuclei-template artifacts. Apply it, unchanged, to every row pulled from Galah before it enters a
train/valid/test split — verified clean on inspection, but re-run the gate programmatically rather than
trusting a manual grep. Extend it with a **refusal-phrase filter** (steal `Rizzy1857/Apate`'s
`_REFUSAL_PATTERNS`, already flagged in `honeypot-projects.md` Tier 1 #1: `as an ai`, `i (can't|cannot)
generate`, `i'm sorry`, leaked code fences, `^here (is|are) (the|a)`): route matches into the DPO
*rejected* bucket instead of discarding them outright — that's how the Galah refusal-tagged 13/40 files
turn from waste into free negative-signal.

## Concrete plan — training round 2

1. **Gate first.** Run the nuclei-poison + refusal filters (above) over every Galah record before touching
   the training set. klukama's two datasets don't reach this step — they're excluded at the modality check,
   not the safety gate.
2. **SFT enrichment (Galah, small).** Reformat the best-model (gpt-4o/gpt-4o-mini/claude-3-5-sonnet/
   gemini-1.5-pro) responses to Galah's 62 real attack paths from `{headers,body}` JSON into funnypot's
   raw-HTML chat turns (drop or defer the header-authoring upgrade — that's Tier 2 in `honeypot-projects.md`,
   a separate piece of work). Mix into the existing 200/20/20 self-distilled split. Expected win: **request-
   distribution realism** — real bot/scanner paths the generator-built corpus doesn't have — not a step-
   change in volume (adds maybe 150–250 rows to 200).
3. **Re-run the LoRA (SFT pass).** Same `mlx-lm` recipe as `funnypot-llm/train/lora.sh`; re-tune iters down
   from 300 given the corpus is still small and the existing run already showed mild overfit (val
   plateaued ~0.22).
4. **DPO pass on top (Galah-sourced, not klukama).** Build chosen/rejected pairs per Galah request (chosen
   = strong-model plausible body, rejected = same-request refusal/degenerate body from a weak model).
   Confirm mlx-lm's DPO trainer support before committing to it; fall back to `trl`/PEFT DPO on the same
   data if mlx-lm's LoRA trainer doesn't cover preference optimization. Apply on top of the SFT adapter from
   step 3, not standalone — reinforces "plausible & juicy" over "boring/refusal/fenced," directly
   answering the DPO ambition in the brief, just sourced from Galah instead of klukama.
5. **Eval.** Extend `eval.py`'s servable-HTML/refusal-rate/length checks with the fingerprint-substring-
   rate check `LLM-TRAINING-BRAINSTORM.md` already specifies (target ~0), plus a spot-check against
   dd-honeypot's 7 golden phpMyAdmin prompts for structural fidelity (not a score, a smoke test).
6. **Backlog, not now:** honeyval integration as a harder adversarial-pentest-agent eval once the round-2
   adapter ships — needs Docker + conda + judge-model API spend, confirm the MIT/Apache-2.0 license
   conflict with upstream first if any redistribution is planned.

**Expect an incremental, not transformative, win.** Galah supplies ~1,380 records over only 62 distinct
prompts — real signal, but thin. The dataset survey confirms what `LLM-TRAINING-DATA.md` already
concluded: the actual lever for a large quality jump is still the **warcprox real-software-recording
pipeline** (stock containers + vulhub + BaxBench, driven by SecLists/nuclei-templates/CSIC-2010 request
corpora). Treat this round as "make the existing LoRA a bit better and add a real DPO pass" while that
bigger pipeline gets built.
