# funnypot: research backlog round 2 (h0neytr4p + web honeypot survey)

_Auto-generated from a 4-stream research workflow (h0neytr4p traps, other web honeypots, fake-vuln ideas, techniques). 78 raw ideas deduped to 32 emulators + 28 techniques, safety-filtered against funnypot invariants (emulate-only, no execution, no OOB, reflect-never-harm)._

## Summary

78 raw ideas deduped to 32 net-new emulators + 28 net-new techniques/features, all respecting funnypot's invariants (emulate output only, never execute attacker input, no OOB/interactsh callbacks, reflect-never-harm). Two themes dominate the high-value end. (1) Anti-fingerprinting is existential: VulnCheck shows a 6000-template inverter is most exposed by its own breadth: static/shared session cookies, contradictory multi-product signatures on one host, blanket 302s on assets, missing real landing markers. Per-request unique session tokens, consistent per-emulator headers, coherent per-host persona chrome, the single-persona contradiction guard, persona persistence, and realistic negative/static responses directly defeat those tells and should lead the roadmap. (2) Exploit-STEP emulators add the marker plain panel-detection can't produce: reflected command output (Ivanti/F5/GeoServer/Solr/ThinkPHP), memory-leaked tokens (Citrix Bleed), created-admin/token JSON (Fortinet/FortiWeb/GoAnywhere/TeamCity/Confluence), and leaked secrets (ownCloud/Actuator/IMDS), reusing funnypot's existing cmd-echo engine, phpinfo emulator, seeded fake-secret/canary machinery, and CVE-2012-1823 handler. Best value-per-effort quick wins are the S-effort emulators that ride existing machinery (PHP-CGI 4577, ownCloud 49103, ThinkPHP) and the S-effort anti-fingerprint techniques. Rejected six ideas already in funnypot's coverage (LFI/XSS/dump classes, .git/.env), collapsed four duplicate clusters, deferred five safe-but-lower L-effort stateful CVEs past the 32-emulator cap, and dropped all OOB/execution/retaliation/LLM-fetch ideas per invariants. Every surviving item is safe=true; the only self-harm vector (bounded tarpit) is gated by hard delay + worker-concurrency caps for PHP-fpm.

## Top 10 to build next

1. Per-request unique session tokens (S/high). Kills funnypot's single loudest VulnCheck tell (static shared JSESSIONID) across every emulator; existential, near-free
2. Consistent fingerprint/framework headers per emulator (S/high). Makes header-recon agree with the body so scanners don't see a bare PHP server behind the fake
3. PHP-CGI CVE-2024-4577 (S/high). One-line %AD/soft-hyphen extension of the existing CVE-2012-1823 handler; huge current scan volume
4. ownCloud CVE-2023-49103 graphapi phpinfo (S/high). Reuse the phpinfo emulator + seeded env secrets; CISA-KEV, among the most-scanned paths since 2023
5. ThinkPHP invokefunction/s-param RCE router (S/high). Route the highest-volume PHP worm probe to the existing phpinfo + cmd-echo emulators
6. Privilege-escalation bait cookie (S/high). Plant role=user, alert HIGH on tamper-to-admin; active tripwire cheaply built on existing canary machinery
7. Spring Boot Actuator emulator /env+/heapdump+/gateway (M/high). Top-scanned Java surface; HPROF blob + seeded env secrets go beyond bare nuclei path match
8. Default-credential acceptance + 6-product login pack (M/high). New deception axis (value-matched creds -> fake success); none of the 6 products currently emulated
9. Cloud IMDS metadata SSRF emulator AWS/GCP/Azure (M/high). Fake credential blobs as canary tokens; header-gated GCP/Azure; in-band only, no outbound
10. Coherent server chrome + single-persona contradiction guard + persona persistence (M-L/high). The anti-fingerprint cluster that stops a 6000-template inverter matching Confluence+F5+QNAP in one host

## New techniques / features

| Technique | Effort | Value | What it does |
|---|---|---|---|
| **Per-request unique session tokens** | S | high | Every emulated response that sets a session cookie (JSESSIONID/PHPSESSID/ASP.NET_SessionId/XSRF-TOKEN) must mint a structurally-valid but UNIQUE-per-connection value with correct entropy/format for the emulated product. VulnCheck de-anonymised a whole cluster of nuclei-matching honeypots purely because they all reused one static JSESSIONID, the single loudest honeypot tell. Marker a scanner checks: cookie value stable/identical across connections and hosts. |
| **Consistent fingerprint/framework headers per emulator** | S | high | Attach a coherent server-fingerprint header set to each product emulator so header-based recon agrees with the body: WordPress -> Server: Apache, X-Powered-By: PHP/7.4, Set-Cookie: wordpress_test_cookie; Tomcat -> Server: Apache-Coyote/1.1, JSESSIONID; ASP.NET -> X-AspNet-Version, ASP.NET_SessionId. Cheap realism multiplier; stops a scanner noticing a bare PHP server behind a WordPress body. |
| **Privilege-escalation bait cookie (tamper-evident honeytoken)** | S | high | Plant a plausible signed auth cookie in emulator responses (role=user / a JWT-looking token / is_admin=0). If a later request replays it modified (role=admin, flipped flag, tampered signature) or reuses a token minted for another attacker, raise a HIGH-severity tripwire. Distinct from passive canary secrets: tampering IS the detection. The token is decorative; no real session verified. |
| **Coherent server chrome per persona** | M | high | A per-host persona profile bundling a consistent Server header, X-Powered-By, header ORDER/casing, Date/ETag/Last-Modified/Content-Length, cookies, and product-specific landing markers (e.g. the confluence-base-url HTML snippet VulnCheck notes fakes lack). Every response for that host draws chrome from one profile so headers never contradict the body. Marker checked: missing real landing page, wrong header order, generic error pages. |
| **Per-attacker persona persistence** | M | high | Deterministically seed the chosen product persona (and its chrome/secrets) from the source IP so a given attacker ALWAYS sees the same server across requests. Prevents the 'same host answers as a different product each probe' tell and reinforces existing seeded-secret consistency. HoneyWeb locks a platform to an attacker for a window and errors on inconsistent requests. |
| **Realistic static-asset & negative responses** | M | high | Honeypots betray themselves by returning 200 for everything or 302-redirecting all .css/.js/favicon requests (both VulnCheck tells). Serve persona-appropriate boring responses: plausible 404/403/401 for unmatched paths, small real-looking asset bodies or honest 404s for CSS/JS/favicon, no blanket redirect. The matched-only guarantee already passes unmatched probes through, so this makes the non-deceptive path look like an ordinary server too. |
| **Content-templating macro system** | M | high | A whitelisted macro layer for emulator templates: {{host}},{{date}},{{version}},{{build}},{{session_id}},{{fake_ip}},{{secret:name}},{{random:pattern}}, all resolved deterministically from the per-attacker seed so values stay consistent within a persona and vary across hosts. Generalises the seeded-fake-secret trick into every body/header. No execution: macros are a fixed set of pure generators. |
| **Probe classification & tool fingerprinting** | M | high | Enrich each logged event with an attack-class/CVE tag and an inferred scanning tool (nuclei/nikto/sqlmap/dirbuster/feroxbuster) derived from UA, header set, path cadence, and payload shape. Turns raw hits into structured intel and lets alerting rank by campaign. Pure classification over already-captured request data; no outbound calls. |
| **Credential-harvest on emulated logins** | M | high | When any emulated login form (wp-login, OWA, Citrix, Tomcat manager, Adminer, phpMyAdmin, generic /admin /manager /user/login) receives a POST, capture username/password/IP/UA/timestamp to the JSON log and return a believable auth-failure (occasionally a fake success setting a decoy session, or a lockout after N tries).
